# Windows 原生运行

源码：D:\x1\x2\PXYMAIL。当前运行目录：E:\pxy-runtime\Mail。使用 Go、PostgreSQL 和 Redis，不使用 Docker、WSL 或虚拟机。

## 网页入口

- 工作站：http://127.0.0.1:3040
- 109：https://pxy.xyz.hr/apps/mail/
- 204：http://43.167.9.204/apps/mail/

远程网页使用 BillionMail 自身的账号登录。工作站必须开机；服务器只代理请求，数据库和发送任务仍在工作站执行。

## 双击入口

- MAILBAT\Start-Mail.bat：启动并打开网页，已经运行时直接打开。
- MAILBAT\Deploy-Mail.bat：构建前端及 Go 后端，成功后更新运行文件并重启 Mail 后端。
- MAILBAT\Stop-Mail.bat：停止 Mail 后端、专用 PostgreSQL 和 Redis。
- MAILBAT\Status-Mail.bat：检查健康状态。
- MAILBAT\Enable-MailAutostart.bat：注册开机和登录启动任务，需要 Windows 管理员权限。当前工作站已注册 PXY-MailNative-Start。

构建需要 Node.js、pnpm、Go；运行需要 PostgreSQL 16 和 Redis。关闭 BAT 窗口后后台继续运行。

## 邮件功能

SMTP 发件配置、模板、联系人和历史记录已保留。发送脚本使用 Mail 自己的配置快照，不再读取 YXHK 的目录。轮换任务允许在预览弹窗明确确认后包含已发送客户；其他发送入口继续沿用原筛选。已保留名单、管理员、退信及退订记录继续排除；退订仍校验 204 上的共享服务。

SMTP 已接收不等于最终送达；没有回执或跟踪数据时页面显示暂无跟踪数据。

Windows 版通过 IMAP 接入已有的 126/163 收件箱，不需要 Linux Postfix、Dovecot、Rspamd 或 Roundcube。

## 收件箱和客户回复

收件箱右上角的“管理邮箱（添加 / 删除）”进入 SMTP 页面。顶部“添加 / 自定义”新增发件账号；账号卡片底部“编辑”和“删除”带图标及文字，删除前仍有确认。临时停用使用卡片右上角开关。前端 UnoCSS 必须输出 icons 层，否则图标按钮会显示为空白。

登录后点击左侧“收件箱 / 客户回复”。系统复用 SMTP 页面保存的邮箱授权码，经 TLS 连接网易 IMAP，自动按账号轮询；每个账号的后台同步至少间隔 15 分钟，不同账号登录至少间隔 20 秒。

- 每次同步原收件箱最近 100 封邮件，缓存最新 10 封正文。查看更早的缓存记录时按需读取正文。
- 单个账号点击“立即检查”，或在列表筛选中选择邮箱后点击“立即检查当前邮箱”，会直接检查原收件箱，完成后自动刷新并显示新增缓存及客户回复数量。同一邮箱手动检查冷却 60 秒，界面显示倒计时；已有连接完成后再执行手动检查，不必等待自动轮询的 15 分钟。
- “安排全部检查”会加入自动轮询队列，仍遵守每账号 15 分钟间隔。点击“刷新列表”只刷新本地记录。
- “客户回复”根据旧发送历史、本项目发送记录及客户名单中的回复标识识别；它是辅助分类，请结合正文判断。
- “退信”是收件内容分类，不会自动变更退订名单，也不代表已接入所有供应商的最终投递回执。
- 点击一封邮件查看正文。“已处理”仅保存到本项目，不改变原邮箱已读状态，不移动或删除原邮件。
- HTML 预览禁用脚本、远程图片和链接跳转；大于 1 MB 的正文及附件请通过“打开原邮箱”查看。
- 账号卡片显示最近同步时间及错误。登录失败时，先确认原邮箱已开启 IMAP/SMTP，并完成网易客户端安全验证；更换授权码后在 SMTP 页面保存。

邮件缓存与处理标记存放于 E 盘专用 PostgreSQL 的 bm_native_inbox_accounts、bm_native_inbox_messages 表。远程 109/204 入口登录后使用相同页面和数据。首次同步多个账号需要数分钟。

脚本支持 -RuntimeRoot 和 -NoBrowser。Agent 调用 BAT 设置 PXY_AGENT_CLI=1，跳过新窗口和暂停。

## 账号与模板轮换发送

发件账号支持“全选可用账号”“清空”“反选”，显示已选数量；全选补充未选账号并保留已调整的账号顺序。选择框最多展开 3 个标签，账号顺序列表可滚动。可选择超过 50 个账号（例如 100 个），仍遵守每账号最多 100 封、每任务最多 1000 位客户的上限。

收件客户可以选择“客户分组 / CSV 名单”或“直接粘贴邮箱”。粘贴支持换行、英文或中文逗号、分号、顿号及空格，按首次出现顺序去重并显示重复、无效项。预览检查发送历史、退信、退订、管理员、其他任务占用和已有联系人状态。粘贴名单可发送人数超过当前容量时显示未分配数量并阻止创建，可点击“按粘贴人数调整上限”后重新预览。预览不写入联系人；确认创建时，在同一事务中保存本次实际名单到“手动粘贴 · 轮换任务 N”分组并创建暂停任务，不修改原分组或历史标记。

“已发送客户的处理方式”默认“发现后弹窗确认”，也可选择“始终跳过已发送客户”。点击预览后，按原名单顺序和本次容量检查已有 SMTP 接收记录；弹窗列出人数及邮箱，并区分相同主题和正文、其他内容、无法核对旧正文。选择“包含已发送客户”后，预览显示再次发送标记；选择“仅发送未发送客户”则重新筛选未发送名单。选择“取消预览”不创建任务。确认只对当前预览生效，每次重新预览或修改配置都重新判断。旧项目明确标记 sent 的历史同样需要确认；退订、退信、失败、待核对、管理员和已占用记录不能通过重复发送确认放行。

确认重复发送不会删除或重置原发送历史。任务配置保存本次确认的历史摘要，创建及逐封调度再次核对；新增其他发送记录、退订或任务占用时暂停并要求重新预览。普通历史没有可靠正文快照时，不声称与当前模板内容完全相同。SMTP 已接收仍不等于最终送达。

打开“邮件营销”，点击“添加任务”，在“发件方式”选择“多账号 / 多模板轮换”；也可从原单账号表单点击“选择多个邮箱轮换发送”，已选邮箱、模板、主题和客户分组会带入轮换表单。“创建轮换任务 / 查看结果”入口继续可用。选择多个 SMTP 账号和多个模板，使用上移、下移调整各自顺序。填写每个模板的邮件主题，选择已有客户分组，或通过分组旁的“创建”导入 CSV。每账号上限填写 2，选择 10 个账号最多发送 20 位客户；默认每封间隔 20 秒。

“每个账号最多发送几封”是上限。实际可发送客户少于总上限时，预览和任务按实际人数生成；仅在没有可发送客户时阻止创建。例如 10 个账号、每账号最多 2 封，只有 19 位可发送客户时，前 9 个账号各 2 封，第 10 个账号 1 封；预览显示实际人数、各账号封数及排除原因。已发送记录按所选方式处理，退信、退订等筛选继续生效。

账号与模板独立循环：第 n 封使用账号 (n-1) % 账号数 + 1、模板 (n-1) % 模板数 + 1。10 个账号、3 个模板时，第 10 封用账号 10 / 模板 1，第 11 封用账号 1 / 模板 2，第 20 封用账号 10 / 模板 2。

点击“预览分配（不发送）”，按需处理重复发送弹窗，逐行检查客户、账号、模板及主题，再点击“确认名单并创建待发送任务”。创建会保留名单，任务初始暂停；下方“开始 / 继续”验证所选账号 SMTP 授权后才发送。未确认再次发送的历史客户以及退信、退订、管理员、发件账号和其他任务占用客户会被排除。原项目迁入且明确标记“未发送待核对”的成员可在单次确认分组中预览核对，其他未确认客户不参与。模板正文及原有链接保持不变。

点击“暂停”阻止后续分配，已经排队或提交的一封可能仍会完成。失败会自动暂停，失败记录不会自动重发；继续仅处理剩余待发送记录。程序重启后任务暂停，保留账号与模板分配；有待核对的 SMTP 记录时禁止自动继续。未发送客户的模板或退订状态变更会再次暂停，需要停止任务并重新预览。点击“详情”查看每封的 SMTP 状态，SMTP 已接收不等于最终送达。

轮换任务保存在当前用户专属 PostgreSQL 的 bm_rotation_jobs、bm_rotation_items 中，沿用本项目邮箱、客户、模板隔离规则。发送统计与客户回复继续使用原生发送记录。

“邮件营销”主列表上方直接显示“多账号轮换任务”，包括创建时间、实际人数、SMTP 已接收、失败、待完成、进度和状态，每 5 秒刷新。点击“详情”在同一页面查看逐封结果。轮换任务创建后即显示，完成后继续保留；普通任务列在下方。搜索同时筛选轮换任务名称、主题等配置和普通任务。轮换子任务仍从普通列表中排除，避免重复显示和绕过轮换顺序操作子任务。
