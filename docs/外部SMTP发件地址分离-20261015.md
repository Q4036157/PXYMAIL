## 基线与边界

Mail 当前不是 Git 仓库，沿用 `deploy/windows/Deployment-20261006.md` 记载的既有例外；本次未初始化仓库，未向 PXYOPS 提交业务代码。`base_commit`（基线提交）及最终提交号不适用。逐文件 SHA256 基线和结果留在本机私有任务记录。

`allowed_paths`（允许路径）：SMTP API、数据库 relay 配置字段、原生发件、轮换任务发件身份、SMTP 前端、普通任务发件人选项、原生域名登记及对应测试。

`forbidden_paths`（禁止路径）：现有收件同步、Postfix 认证、客户运行数据库和凭据、服务器部署、套利项目。

## 根因与修改

- 原生发件曾将 `auth_user`（SMTP 登录名）同时当作发件邮箱，无法接入登录名不同于 From 地址的外部服务。
- 新增可选 `sender_email`（实际发件地址），默认空；旧配置回退原登录名，不改变原 126/163 账号。SMTP 认证仍使用原登录名。
- 创建和更新校验实际地址属于所选发件域名。更新字段未传时保留；显式空字符串清除并回退旧行为。
- 发件查找、轮换预览和执行、排除发件人统一采用实际发件地址。普通任务合并可用的 SMTP 发件身份，不假造本地收件账号；按域名筛选并去重。
- 工作站添加域名只登记外部发件域名，不创建默认本地邮箱、不修改 Docker 邮件服务、不申请本地邮件证书；拒绝不支持的本地全收邮箱和专用发信 IP。
- 新增数据库列仅写入初始化迁移代码，尚未在运行数据库执行。发布前需按现有规范对相关配置表作定向备份、核对租户并验收旧配置。
